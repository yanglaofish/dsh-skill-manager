# 技能库双入口

## 结构

`SkillManagerPanel` 负责两处管理页面，`presentation` 只控制布局与默认视图：

- `panel`：原生侧栏“技能库”，宽屏、双栏卡片、页面内滚动。
- `settings`：设置里的“技能管理”，紧凑列表，随设置容器滚动。

顶部只保留标题、当前标签页的一句使用提示和操作按钮；技能总数放在“全部技能”标签旁。
不单列预设数、工作区数或统计横条，版本号通过标题悬停查看。

会话“技能”继续复用 `WorkspaceSkillsPanel`。技能的导入、编辑、删除、搜索、预设只读、工作区默认选择与会话独立选择不改变。此次不增加分组或命名空间。

## 生命周期与同步

原生 `main` 注册的 `key` 与 `sidebar.panellist` 的 `id` 均为 `skill-manager`。
两个槽均就绪才注册侧栏行；任一槽离开时撤销行，并退出被移除的活动页面。设置页不依赖原生侧栏槽或 layout 服务。

统一 API 包装在成功 POST 后发送本客户端内的变更通知，失败或 GET 不通知。
每个面板在卸载时取消订阅；会话通知只刷新相同会话，工作区通知只刷新相同目录。
发起工作区/会话写入的组件自行处理结果，避免自身通知抢先使保存回调失效。
列表和搜索请求使用序号丢弃过期响应，刷新不清空搜索词、布局选择或正在编辑的详情。
通知不跨浏览器窗口或 profile 进程；重新打开页面会读取最新数据。

## 验证

- `npm test`：包含槽延迟注册/撤销/重挂、缺少侧栏兼容、成功写入通知、会话隔离和保存提示回归。
- `scripts/ui-smoke.cjs`：真实 React 渲染本地 bundle，API 仅用内存样本。
  检查宽屏、紧凑、深色、390px 布局无横向溢出，双面板删除与搜索结果同步。
  这不是桌面端到端测试，不读取真实用户技能或桌面认证信息。

运行 UI 验收需要 Playwright、Chrome，以及放在工作区 `logs/skill-manager-ui/` 的 React 18.3.1 UMD 文件
`react.js`、`react-dom.js`。可以通过 `PLAYWRIGHT_PATH` 和 `CHROME_PATH` 指定本机运行环境，
截图也输出到该目录。这些仅用于验收，插件运行不增加依赖。

验收必须使用宿主的真实主题，不能手动补齐宿主不存在的变量。
先运行 `node scripts/run-desktop-test.mjs <桌面目录绝对路径> scripts/export-desktop-theme.cjs`
导出 `host-theme.css`，再运行 `node scripts/ui-smoke.cjs`。
验收检查导入按钮在亮色、深色及悬停状态下的背景非透明、文字对比度至少为 4.5:1，
并实际打开目录选择、上传示例技能与附件，确认列表更新。
